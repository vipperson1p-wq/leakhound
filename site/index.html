How it works

  1. 01 · Run

    One command, no setup

    npx leakhound in your project folder. It reads the files git would publish, plus your migrations, in about a second.

  2. 02 · Read

    Findings in plain words

    Each issue says where it is, why it is dangerous and how to fix it. Same issues are grouped, keys are masked.

  3. 03 · Fix

    Or let your AI do it

    Connected over MCP, Claude Code or Cursor gets the report and applies the fix with you.

What it sniffs out

The mistakes AI coding tools make most often in Next.js, Vite and Supabase projects. Every finding has a severity, so you know what to fix first.

  • critical
  • high
  • medium
  • low
  • keyscritical

    API keys in code

    OpenAI, Anthropic, Stripe, AWS, GitHub, Google and the Supabase service_role key. The anon key and placeholders are left alone.

  • public envhigh

    Secrets in public variables

    NEXT_PUBLIC_, VITE_ and REACT_APP_ variables are shipped to the browser. LeakHound flags the ones holding secrets.

  • .envcritical

    .env files in git

    Catches .env files that are committed, or will be with the next git add, and a .gitignore that does not protect them.

  • supabasecritical

    Tables without RLS

    Reads your migrations: tables without Row Level Security, policies with USING (true), and tables whose RLS cannot be verified from code.

  • --historycritical

    Keys hiding in history

    Deleted a key from the file? It still lives in old commits. LeakHound scans the whole git history.

  • install-hookguard

    Pre-commit guard

    A git hook that blocks a commit with a critical leak before it ever reaches GitHub.

Private by design

  • Runs locally. No servers, no uploads, no account.
  • Keys are masked in every output: terminal, JSON and MCP.
  • Code from your repo is marked as data for your AI, never as instructions.
  • Open source under MIT, so you can read exactly what it does.

Honest about its limits

“No issues found” is not “fully secure”. Every report lists what LeakHound does not check:

  • Your live database: only migrations in code are checked.
  • Access logic in your API routes.
  • Vulnerable dependencies (use npm audit).
  • Built output in .next or dist.
  • Hosting settings: Vercel env variables, CORS, headers.
  • XSS, SQL injection and prompt injection.
